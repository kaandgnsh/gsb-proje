# M12 — Linux çevrimdışı paket adayı ve Windows tarifleri

Durum: Linux x86_64 paket akışları doğrulandı. Bu, temiz VM veya dağıtım geneli
uyumluluk sertifikası değildir. Windows gerçek ortamı ve hedef 4B model kalite
testleri bekliyor. Yalnız sentetik sınav verisi kullanıldı; model indirilmedi,
gerçek sisteme kurulum, push veya yayın yapılmadı.

## Başlangıç ve paket

M11 güvenlik raporu, M12 ana planı ve kurulum betikleri incelendi. Başlangıç
referansı **747 teknik test geçti**; önceki 16 gerçek entegrasyon testi seçilmedi.
M11'deki mevcut Linux 9B yerel çıkarım sonucu korunuyor; M12'de yeniden model
kalite testi yapılmadı.

Üretilen dosyalar:

- `dist/lai-0.12.0-linux-x86_64.AppImage` — 361.908.728 bayt, x86_64.
- `dist/lai-0.12.0-linux-x86_64.AppDir/` — doğrulanabilir, çıkarılmış paket.
- `dist/build-tools/appimagetool-x86_64.AppImage`,
  `dist/build-tools/appimagetool-root/` ve `dist/build-tools/runtime-x86_64` —
  yerel yeniden üretim girdileri. Çıkarılmış appimagetool dizini FUSE gerektirmez.
- `dist/SHA256SUMS` — AppImage ve iki üretim girdisinin SHA256 özetleri.

AppImage uygulama, bağımlılık ve standart kütüphane snapshot'ı içerir; Ollama ve
model içermez. Bu geliştirme ortamından alınan 30 Python dağıtımını içerir;
minimal veya her Linux'a taşınabilir bağımlılık seti iddiası değildir. Paket
manifesti tam dosya listesi, SHA256, Python, libc, mimari, bağımlılık ve sistem
önkoşullarını kaydeder. `glibc`, bubblewrap, libseccomp ve Wayland sistemde
gereklidir. Bileşen oluşturucu, yerel Ollama ikilisini ve model blob/manifests
deposunu ayrı paketler; model katman özetlerini kopyalamadan önce doğrular. Gerçek
runtime/model bileşen paketi üretip kurma bu testte yapılmadı.

AppImage üretim aracı ve type-2 runtime resmi AppImage GitHub sürüm girdilerinden
alındı, SHA256'ları yukarıdaki dosyayla eşleşti. İndirme yalnızca paket üretim
araçları içindi; model veya kurulum bağımlılığı indirilmedi.

## Kurulum ve çalışma

AppImage normal başlatma, kurulu launcher ve desktop kısayolu aynı `AppRun` →
`package_entry` yolunu kullanır. Normal uygulama bu yoldan M11'in zorunlu Linux
yalıtımını kurar; hata halinde değerlendirme başlamaz. Paket doğrulaması tam dosya
envanterini, izinleri ve SHA256'ları kontrol eder. Bakım arayüzü runtime/model
başlatamaz. Uygulama kendine ait `LAI_HOME` altında SQLite, rapor, runtime ve
modeli ayrı tutar; varsayılan kaldırma uygulama sürümlerini/başlatıcıyı kaldırır,
kullanıcı kayıtlarını ve bileşen depolarını korur. Dolu runtime/model deposunun
üzerine yazma reddedilir.

Örnekler:

```bash
# AppImage'ı doğrudan başlat: normal arayüz M11 yalıtımıyla açılır
./dist/lai-0.12.0-linux-x86_64.AppImage

# Yerel AppDir ve AppImage üret; hiçbir girdi indirilmez
PYTHONPATH=src .venv/bin/python -m lai_setup bundle \
  --output dist/yeni.AppDir \
  --appimagetool dist/build-tools/appimagetool-root/AppRun \
  --appimage-runtime dist/build-tools/runtime-x86_64

# AppImage içindeki aynı paket yoluyla kullanıcı köküne kur/denetle/onar/kaldır
./dist/lai-0.12.0-linux-x86_64.AppImage --setup install --lai-home /tmp/lai-home --yes
/tmp/lai-home/yerel-envanter --setup doctor --lai-home /tmp/lai-home --json
/tmp/lai-home/yerel-envanter --setup repair --lai-home /tmp/lai-home --yes
/tmp/lai-home/yerel-envanter --setup uninstall --lai-home /tmp/lai-home --yes

# Ollama ve model paketlerini ayrı üret; kaynak dizinler yerel olarak sağlanmalıdır
PYTHONPATH=src .venv/bin/python -m lai_setup bundle --component runtime \
  --source /yerel/ollama-bin --output dist/runtime.AppDir
PYTHONPATH=src .venv/bin/python -m lai_setup bundle --component model \
  --source /yerel/ollama-model-deposu --output dist/model.AppDir
```

Üretim komutunda çıkarılmış yerel `appimagetool-root/AppRun` kullanılır; AppImage
biçimindeki araç bu ortamda FUSE aygıtı olmadığı için doğrudan başlatılamadı.

Uygulama verisi olmayan boş bir kökte `install` ve ikinci `install`, bozuk sürümün
`repair` ile onarımı, sürüm/hash güncelleme, `doctor` ve `uninstall` geçişleri
çalıştırıldı. Güncelleme SQLite backup API ile veri yedeği alır; tekil değerlendirme,
profil sürümü ve geçmiş PDF raporu korundu. Paket doğrulama hatası hedefe yazmadan
önce üretildi. Kullanıcının gerçek sistemine kurulum yapılmadı.

## Kabul akışları

Geçici kullanıcı kökü ve `unshare -Urn` ağ ad alanı içinde 4, 12 ve 28 sorulu
sentetik envanterler gerçek paket girişinden içe aktarıldı. Her envanterde cevap
doğrulama, tekil CLI sonucu, JSON/PDF/CSV/XLSX raporları, geçmiş sonucu yeniden
açma ve CSV + XLSX toplu işi çalıştı. Toplu iş bir katılımcıdan sonra kapatılıp
ikinci CLI çalıştırmasında devam etti; başlangıç envanter/profil sürüm kimlikleri
korundu ve sonuçlar tekrarlanmadı. Bu sayılar ilgili envanter sürümünden alındı;
400 yalnız performans testinin eski girdisidir.

Kabul komutu: `PYTHONPATH=src:tests/support unshare -Urn .venv/bin/python
tests/packaging/accept_installed.py <AppRun> <geçici-dizin>`. Gerçek paket
başlangıç yolu ve kayıtlı CLI servisleri kullanıldı; kabul özeti JSON olarak
saklandı.

İkinci/onarım/kaldırma ve kendi kendini kurma testi AppImage'ın gerçek girişinden
aynı ağ kapalı laboratuvarda geçti. Normal AppImage GUI'si ayrı D-Bus ve geçici
Wayland sanal compositor'ünde açıldı, SQLite oluşturdu ve yalıtılmış alt süreç
kanıtlandı. Bu GUI duman testidir; M11'deki uçtan uca Qt akış testlerinin yeni bir
insan kullanılabilirlik veya temiz kurulum tekrarı değildir.

Paket içi kendinden kurulum/onarım/kaldırma:
[lifecycle.json](assets/m12-linux/lifecycle.json). GUI başlangıç duman testi:
[gui-startup.json](assets/m12-linux/gui-startup.json).

Paketlenmiş gerçek `AppRun` kontrollü pozitif hedeflerde test edildi. Yalıtımsız
kaynak ve alt süreç kontrolleri 12/12 yol üzerinden hedefe ulaştı; aynı paket
başlatıcısında IPv4/IPv6 TCP/UDP, DNS, loopback/Unix/abstract Unix proxy ve glibc
NSS/resolved yollarının 12/12'si engellendi; kolektöre yeni paket sayısı sıfırdı.
Yalnız ağ namespace kontrolünde dosya Unix proxy ve resolved varlink sızıntısı
pozitif kontrolde tekrar görüldü. Paketlenmiş yol bu sızıntıları M11 seccomp
sınırıyla kapattı. Paket ağı kanıtı:
[packaged-network.json](assets/m12-linux/packaged-network.json).

Değişken envanter kabul özeti:
[offline-acceptance.json](assets/m12-linux/offline-acceptance.json).

## Windows

`packaging/windows/` içinde PyInstaller spec, Windows giriş modülü, PowerShell
derleme betiği ve Inno Setup tarifi hazırlandı. Derleme betiği Windows dışı
ortamda durur; Inno varsayılan olarak LocalAppData'ya kurar ve kullanıcı verisi
silme adımı tanımlamaz. Çalıştırma, **M11'in Windows güvenlik kapısını korur**.
Bu Linux ortamında PowerShell, PyInstaller Windows build ve ISCC gerçek derlemesi,
GUI, ağ yalıtımı, Ollama süreç sahipliği veya kaldırma çalıştırılmadı. `.exe`/
kurulum paketi teslim edilmedi; Windows doğrulanmış sürüm değildir.
Python giriş/spec dosyaları AST ile ayrıştırıldı; bu kontrol PyInstaller derlemesi
veya Windows doğrulaması değildir.

Windows'ta doğrulama için (gerçek Windows x64, Python/PyInstaller ve Inno Setup
kurulu): `pwsh -File packaging/windows/build.ps1`; ardından kurulum, iki kez
başlatma, kullanıcı verisi koruyan güncelleme/kaldırma, GUI ve Alt+F4, M11 kapısı
kapalıyken açıklayıcı engel, uygulama Ollama'sının kendi PID ağacında kapanması,
kontrollü IPv4/IPv6/DNS/Unix broker testleri. Bunlar geçmeden Windows paketi
doğrulanmış olarak adlandırılmamalı.

Başlangıç: **747 teknik geçti, 16 eski gerçek entegrasyon testi seçilmedi**.
M12 testleri sentetik: paket şeması/bütünlük ve bozuk dosya reddi, AppRun izin
tamiri, kurulum/tekrar/onarım/güncelleme/kaldırma veri koruması, ayrı runtime/model
bileşenleri, hatalı blob, kendinden kurulum, bakım güvenlik kapısı ve paketlenmiş
giriş testleri. Nihai tam teknik takım: **759 geçti, 0 başarısız, 16 eski gerçek
entegrasyon testi seçilmedi; 264,75 sn** (Linux x86_64). Başlangıçtan 12 yeni
paketleme testi eklendi. `compileall` ve değiştirilen/yeni kodda `ruff check`
geçti. Gerçek Windows ve model kalite kontrolleri tam teknik testlerden ayrı
bekleyen doğrulamalardır.
